# Token efficiency

Optimize total work to a correctly completed task. Preserve the user's required scope, detail, quality, freshness, evidence, safety and permissions.

- Reuse accepted artifacts and still-valid results. Check relevant changes cheaply; refresh time-sensitive facts when needed.
- Locate before reading: search targeted paths or headings, then read enough surrounding context. Expand when dependencies or uncertainty require it; never treat an excerpt as complete evidence.
- Use existing deterministic scripts for repeatable mechanical work. Avoid a model call for a known rule. Batch independent reads; delegate only distinct work with a useful speed or quality benefit, without repeating a completed analysis.
- Keep mandatory checks and requested deliverables. Rerun completed checks only after relevant changes, failures or unresolved concerns. Do not shorten requested content or stop early to save tokens.
- Retain goals, constraints, user decisions, authorization and unresolved items. Drop stale tool detail before essential context. Do not rewrite a stable cached prefix merely to shorten it; compare total cost when cache usage is available.
- Keep the chosen model, reasoning settings and services. Do not introduce Jev or another paid service, or send private material elsewhere, merely to optimize.
- Simple requests need no optimization preflight, score, report or extra agent. If there is no clear avoidable work, proceed normally.
- Claim savings only from comparable provider usage measurements. Counts of files, characters or calls are proxies, not measured token savings.
